# Wendy Moore Gallery

A React/Vite media gallery with an Express API, MongoDB metadata, and local or S3-compatible file storage.

## Setup

1. Install Node.js 22 or newer and MongoDB.
2. Run `npm ci`.
3. Copy `.env.example` to `.env`, set `UPLOAD_PASSWORD`, and configure `MONGO_URI`.
4. Run `npm run build`, then `npm start`. The gallery is served at `http://localhost:3001`.

For development, run `npm run server` and `npm run dev` in separate terminals. Vite runs on port 8080. Optional video thumbnails and dimensions require `ffmpeg` and `ffprobe`; unavailable codecs do not prevent uploads.

## Configuration

- `UPLOAD_PASSWORD`: server-only password for uploads, edits, and deletion.
- `MONGO_URI`: MongoDB connection string.
- `PORT`: backend port, default `3001`.
- `UPLOADS_DIR`: optional local upload directory, default `uploads/`.
- `VITE_API_URL`: optional separate API host. Production defaults to the current origin; development uses `http://localhost:3001`.
- `FRONTEND_ORIGINS`: comma-separated additional frontend origins for CORS. Local Vite origins on port 8080 are included by default.
- S3 settings are documented in `.env.example`. Leave credentials empty to use local storage.

Never put the upload password in a `VITE_` variable. If an older build used `VITE_UPLOAD_PASSWORD`, rotate that password and rebuild the frontend. Deploy the frontend and backend together: uploads now authenticate with an `Authorization: Bearer <URL-encoded password>` header before file data is accepted, and send one file per request. Editing and deletion accept the password in their JSON body.

Hold **Ctrl+Shift** to reveal Edit and Delete actions on media cards. Health status is available at `/api/health`.

## Media loading

The gallery renders 24 cards per page. Search, sorting, and date filters cover the full collection. Previews load within 160px of the viewport, with at most four simultaneous requests. Leaving a page cancels its preview work; stalled requests release their slot after 30 seconds.

Videos use existing thumbnails or placeholders and download only for playback. Images prefer thumbnails; older images without thumbnails still load originals through the same request limit. Metadata is fetched in one API request. Viewer and upload code load only when opened.

## Checks

```sh
npm run build
npm run lint
npx tsc --noEmit -p tsconfig.app.json
npm run test:server
npx playwright install chromium
npm test
```

To test with an installed Edge or Chrome browser, set `PLAYWRIGHT_CHANNEL=msedge` or `chrome`. Browser tests include a 2,400-item collection, uploads, date editing, and responsive layouts. Server tests use temporary files and mocked database/storage operations; neither suite modifies production data. Screenshots are written to the ignored `test-results/` directory.

## Optional maintenance

Run these from the project root only when needed:

- `node scripts/migrate-to-s3.js --dry-run`: preview a local-to-S3 migration. `--verify` checks existing S3 objects; running without flags performs the migration and creates a database backup in `backups/`.
- `node scripts/fix-s3-urls.js`: update legacy Contabo URLs to include the configured tenant ID. This changes database records.

Keep `uploads/`, `.env`, and `backups/` outside version control. `dist/` and `node_modules/` are generated by the build and dependency installation.
